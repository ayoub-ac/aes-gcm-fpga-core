# Synthesis comparison report

Generated by `make synth_report`. Numbers are post-synthesis, pre-place-and-route.
Vendor flows (Vivado / Quartus) usually pack tighter than the open-source flow,
so the Yosys numbers should be read as upper bounds.

|--------------------------|-------------------------|------------------------------|
| Yosys 0.x synth_ice40    | iCE40 UP5K              | 8243 LUT / 3379 FF / 32 BRAM              |
| Yosys 0.x synth_ecp5     | ECP5 LFE5UM-25          | 17907 LUT / 3637 FF / 0 BRAM               |

## Notes

* The dominant area is the GHASH GF(2^128) multiplier and the AES-128
  cipher pipeline. The shipped GHASH is a 128-cycle iterative
  shift-and-add multiplier — small in LUTs but slow per multiply.
  Vendor flows (Vivado, Diamond, Quartus) do NOT fold this into DSP
  slices because GF(2^128) multiplication is XOR-based, not integer
  multiplication; the carry-save / Karatsuba / pipelined Karatsuba
  variants are on the Premium roadmap.
* The AES-128 core is the iterative one-round-per-cycle implementation
  shared with `aes128-fpga-core` (one S-box per byte, combinational
  ShiftRows / MixColumns / AddRoundKey). At ~12 cycles per encrypt it
  takes ~12 cycles per CTR keystream block plus ~128 cycles per GHASH
  absorb — so GHASH dominates total latency, not gate count.
* iCE40 numbers are dominated by SB_LUT4 cells for the AES round and
  GHASH XOR tree. Total state: 128b key + 96b nonce + 128b H + 128b E0
  + 128b GHASH acc + 32b CTR + 64+64b length counters + ~700b FSM /
  buffer registers ~ 1300 FFs.
* Xilinx generic numbers count Yosys's primitive cells before Vivado's
  LUT6 and SLICEM packing. Real Vivado synth_design typically produces
  ~30-40% fewer LUTs.
* Vivado / Quartus rows are skipped automatically when those tools are
  not on PATH; on a CI runner with WebPACK / Web Edition installed they
  will be populated from a real synth_design / quartus_sh run.
